# ECGC 方法细则与反例库

## 一、四工序不可合并
抽取（E）→ 建边（C）→ 对齐（G）→ 查询（CQ）是四道独立工序。抽取阶段只管"实体是否真实出现"，对齐阶段才判同异，核验阶段独立回扫。禁止一边抽一边凭常识"顺手补个更标准的实体名"。

## 二、机制 E：证据约束抽取
合格实体须同时满足：
- **真实出现**：实体对应论文里真实出现的科研对象（研究者/材料/方法/任务/指标/结论），保留原文表述，不用常识补全概念。
- **来源可定位**：每个实体带 `source_id` + `paragraph_id`（JATS 段落 ID）+ 原文短引。
- **转述区分**：`self_reported`（作者自述）与 `paraphrased`（他人转述）分开；综述转述不是直接证据。
- **无证据不建**：找不到原文支撑的实体标 `unverified`，进 `uncertainties`。

## 三、机制 C：受控关系抽取
- **有证据才连**：每条边必须有原文支撑，记关系类型（受控词表）、方向、适用条件、来源、短引。
- **禁止三类伪关系**：共现 ≠ 关系；综述转述 ≠ 直接证据；推测 ≠ 事实。
- **方向校验**：subject→predicate→object 的方向与原文一致，主体不得张冠李戴。

## 四、机制 G：受控实体对齐
- **给依据**：合并（全称=缩写、规范大小写、同 DOI/同标识符）或不合并（不同对象、不同条件/样本/数值）都要写明 `basis`。
- **三个不强迫**：不强迫每个别名都合并；不把不同论文的条件/样本/数值结果合成一个结论；相同通用方法/材料术语不代表两篇用了相同物理样品/模型实例/数据集/实验条件。
- **可追溯**：`merge_decisions` 与 `conflicts` 全部留痕，进 `human_review_items` 的项要具体。

## 五、机制 CQ：来源绑定与可回查查询
- 每个节点和边都保留独立论文的 `source_id`、`paragraph_id`、原文短引与证据强度。
- 至少 3 个**实际执行**的查询，给结果子图（节点/边 ID）、支撑证据、无法确定项。无结果如实返回空子图。

## 六、反例库
| 反例 | 为什么错 | 改法 |
|---|---|---|
| 实体写成"深度学习模型"这类常识概念 | 论文里未真实出现，凭常识补全 | 改用论文原文表述并标位置短引 |
| 把"A 提到 B"的综述转述建成 A→B 直接关系 | 转述当直接证据 | 标 `paraphrased`，不作为直接边或降证据强度 |
| 两篇论文的"准确率 90%"合并成一个指标实体 | 不同论文条件/样本/数值被揉成一条 | `keep_separate`，分别保留各自来源 |
| "材料 X"在两篇都出现就判同一物理样品 | 通用术语≠相同样品/数据集/条件 | `keep_separate`，进 human_review_items |
| 用自建"第 1 页"当位置 | 本包无 PDF 页码，回不到原文 | 用 JATS 段落 ID |
| 把根 DOI/作者套到第二篇 | 跨篇元数据混用 | 逐篇独立登记来源 |
| 同篇 JSON 与 Markdown 当两篇证据 | 同篇多格式不算跨篇证据 | 按 `source_id` 合并为同一篇 |
| 查询"哪些结论矛盾"直接编几条 | 未在图上执行、无证据 | 实跑查询，回填节点/边 ID 与短引 |

## 七、抽取与核验分离
构建阶段禁止自我核对；完成后以"审阅者"身份执行 checklist（实体落地/关系有证/对齐有据/查询有证），每次改动写 change_log。材料缺失、无法判断、运行失败分别说明，不编造数据、来源与 benchmark 分数。
