# 实体/关系类型定义与对齐规则

## 1. 实体类型（type，受控）
| 类型 | 含义 | 例（示意） |
|---|---|---|
| `researcher` | 真实出现的研究者/作者 | 论文署名作者 |
| `material` | 材料/数据集/样品 | 文中命名的数据集 |
| `method` | 方法/模型/算法 | 文中提出的方法 |
| `task` | 任务/问题设定 | 分类、回归任务 |
| `metric` | 指标 | 准确率、F1 |
| `conclusion` | 结论性论断 | "X 优于 Y" |

每个实体必带：`entity_id`、`name`（原文表述）、`type`、`source_id`、`paragraph_id`（JATS）、`quote`（原文短引）、`mention_type`、`evidence_strength`。

## 2. 关系类型（predicate，受控）
| 类型 | 含义 | 证据要求 |
|---|---|---|
| `uses` | 使用（方法→材料/数据） | 原文明确"使用/采用" |
| `compares` | 比较 | 原文明确对比两对象 |
| `outperforms` | 优于 | 原文明确优劣且方向清晰 |
| `supports` | 支持（证据→结论） | 原文明确支撑关系 |
| `contradicts` | 矛盾 | 原文明确冲突 |
| `other` | 其他 | 须在 quote/condition 保留原文表述 |

**禁止**把共现、综述转述、推测标为上述强关系；不满足则不给边。

## 3. 证据强度
- `strong`：原文直接陈述，短引逐字可查，位置精确。
- `weak`：需跨句推断或来自转述（paraphrased），进人工复核倾向。

## 4. 别名对齐规则（机制 G）
合并的**充分依据**（满足其一且无反证）：
- 全称 ↔ 公认缩写（首次出现处可核对）；
- 大小写/连字符规范差异且指向同一原文对象；
- 同 `source_id` 内同一实体的不同写法。

**不得合并**（任一成立即 `keep_separate`）：
- 两篇论文的不同条件、样本、数值结果；
- 相同通用术语但不同物理样品/模型实例/数据集/实验条件；
- 同名但语境不同的对象（同名冲突）。

## 5. 冲突处置
`conflicts` 记录冲突的关系/实体对、描述与 `handling`（保留并标注/降证据强度/进人工复核）。不得为"图干净"而删除冲突或强行选边。

## 6. 位置与来源
- 位置一律用组织方给的 JATS `paragraph_id`，**不是 PDF 页码**。
- 每个节点/边用独立论文的 `source_id`；根 DOI/title/authors 属于第一篇，不得套到第二篇。
- 同篇多文件格式（JSON/Markdown）不算跨篇证据，按同一 `source_id` 处理。
- 不推断补充附件、底层临床/实验数据中的数值；未报告与源内冲突明确保留。
